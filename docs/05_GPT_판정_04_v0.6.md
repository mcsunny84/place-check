- 검토일: 2026-09-14.

## 0 총평(구현 착수 가능 / 조건부 / 반려)

**판정: 조건부. 산식과 보충 기본 흐름은 구현할 수 있으나, 자동 판정 공통 규칙의 우선순위는 그대로 구현하면 안 된다.**

R2 13건 중 **해소 5건, 부분 8건, 미해소 0건**이다. R2-1의 Blocker는 부분 해소 상태로 남는다. `missing/empty/value` 구별은 개선됐지만, “행 규칙보다 우선”하는 `전부 empty → fail`이 A3·C4·D3의 명시적 예외와 충돌한다. 수치·날짜의 유효한 값에서 나오는 fail 및 D2의 n/a도 공통 규칙에 제대로 수용되지 않았다. 이는 표현 취향이 아니라 같은 facts의 결과를 달리 만드는 문제다.

R2-2의 계산 Blocker는 해소됐다. 신규 발견은 **Major 1건·Minor 1건**이며, 신규 Blocker는 없다. 재설계나 기능 추가는 필요 없다. 아래에 적은 판정 우선순위·종료 경로·정규화 제한을 확정하고 기존 범위에서 구현하면 된다. 추가 설계 라운드 대신 §4를 구현·리뷰의 최종 기준으로 사용할 수 있다.

### 1.1 §1.1 전 행과 §1.0 공통 규칙 대조

아래 “일치”는 필드의 유효 타입과 부재 의미를 실제로 확인한 경우에 한한다. `empty_means_absent`가 아직 확인되지 않았다면 빈 값만으로 fail을 만들지 않는다. 아래 R2 잔여 문제에는 신규 R3 번호를 중복 부여하지 않았다.

| ID | 점검 | 근거·최소 처리 |
|---|---|---|
| A1 | 일치 | 유효 번호 하나 pass, 두 번호의 확인된 부재 fail, 나머지 unknown. |
| A2 | 충돌 | `openingHours=empty, hideBusinessHours=true`는 행상 unknown이지만 공통 규칙을 openingHours에 적용하면 fail. 반대로 숨긴 7일 정보 value는 공통 긍정 우선으로 pass 가능. **hide=true를 먼저 unknown 처리**, false 확인 후 요일 판정. hide 미관측도 숨김 여부를 판단하지 못하면 unknown. |
| A3 | 충돌 | breakTime·정기휴무 원천이 전부 empty이면 공통 fail, 행은 unknown. 자동 empty는 unknown, 수동 ‘아니오’만 fail, ‘우리 가게 없음’은 n/a로 고정. |
| A4 | 일치 | 필드 확정 전 missing, 확인된 유효 안내 pass, 미등록 의미까지 확인된 empty fail. §7-1이라는 참조 번호 오류는 Minor. |
| B1 | 조건부 일치 | 값의 NFC→trim→코드포인트 수를 적용하면 pass/partial은 일치. 공백뿐인 원문은 정규화 후 길이 0으로 fail에 연결해야 함. 정규화 전 비어 있지 않다는 이유로 value에 고정해 판정 누락을 만들지 않음. |
| B2 | 조건부 일치 | 유효 개수 0~5는 일치. 길이 6 이상·원소 타입 오류를 유효 value로 통과시키지 않고 unknown으로 처리. 원문 배열 확인과 기본 빈 배열은 구별. |
| B3 | 충돌/모호 | 메뉴 A의 price=empty, 메뉴 B의 price=missing인 경우 “그 메뉴 제외” 뒤 partial을 내면 미관측 감점. 가격 value 하나는 pass; **모든 메뉴 가격의 부재를 확인했을 때만 partial**; empty+missing은 unknown. |
| B4 | 일치 | 메뉴 이미지 또는 메뉴판 사진의 유효 증거면 pass. 두 원천 모두의 부재를 확인해야 fail. 메뉴별 images 일부 미관측을 전체 빈 값으로 합치지 않음. |
| B5 | 공통 규칙 불완전 | 유효한 수량 3은 value지만 행에서는 fail이다. 공통 규칙은 긍정/전부 empty/missing만 열거하여 이 경우가 빠짐. 수량을 읽었으면 행의 0~4/5~19/20 이상 경계를 적용. 0은 missing이 아님. |
| B6 | 공통 규칙 불완전·최신성 잔여 | 유효한 91일 전 날짜는 value에서 fail. 또한 읽힌 목록 최대값이 오래됐다는 사실만으로 전체 최신 소식이 오래됐다고 확정하면 안 됨. 아래 1.3 참조. |
| B7 | 일치 | 관련 링크 하나 pass, 전부 부재 확인 fail. naverBlog 하나 empty이고 나머지 원천 missing이면 unknown. |
| C1 | 조건부 일치 | true는 pass, 명시 false는 fail. generic empty에는 null·빈 문자열 등도 포함되므로, 이 필드에서는 **유효한 false와 그 밖의 잘못된 타입을 구분**. n/a는 수동 명시 선택. |
| C2 | 조건부 일치 | 활성 근거로 확인한 톡톡 URL 또는 0507 번호 하나면 pass. A1에 쓸 수 있는 번호 value라고 해서 C2에도 자동 pass는 아님. §7-14 결과 전에는 활성 미확인 unknown. |
| C3 | 부분 일치 | 유효한 진행 중 항목 하나면 pass, 기간 missing만으로 fail 금지. 예정 항목만 있는 경우는 신규 R3-1. 빈 목록/만료분 판정에도 공통 empty의 의미 확인 필요. |
| C4 | 충돌 | 두 원천 empty이면 공통 fail, 행은 명시적으로 unknown. 자동 empty는 unknown으로 예외 처리. ‘주차 불가’ 등록은 value이며 pass라는 문항 의미는 맞음. |
| D1 | 공통 규칙 불완전 | 181일 전 작성일은 value에서 fail. 총수 value=0이면 날짜가 missing이어도 fail이 우선이어야 함. “하나라도 missing→unknown”을 먼저 적용하면 리뷰 없음이 사라짐. |
| D2 | 충돌 | D1 리뷰 없음/총수 0이고 답글 날짜 missing이면 행은 n/a, 공통은 unknown. **리뷰 없음에 의한 n/a를 최우선**으로 적용. 일반 fail 상태의 D1만으로 n/a를 만들지 않음. |
| D3 | 충돌 | description=empty·소식 목록=empty이고 모두 확인됐다면 검사 완료·미검출이므로 행상 pass, 공통은 fail. 읽힌 부분 검출 fail, 검사 범위 전체 확인 후 미검출 pass, 나머지 unknown이라는 전용 규칙 필요. |

**R2-1을 닫는 최소 우선순위:** §1.0을 모든 행을 대체하는 상태 판정기로 쓰지 말고 관측 해석 규칙으로 한정한다. (1) 명시 n/a 및 D1→D2 종속, A2 숨김 같은 행의 선행 조건 → (2) 관측된 값으로 확정 가능한 행 결과 → (3) 부재·완전성 확인이 필요한 행의 결과 → (4) 나머지 unknown. OR의 긍정 증거는 반대편 missing과 공존해도 pass지만, A3·C4·D3에 보편적인 empty→fail을 적용하지 않는다. B5 등의 유효 값에서 나오는 fail도 행 결과에 포함한다. 필요한 원천이 무엇인지는 각 행으로 한정한다.

### 1.2 §2 산식·검산 결과

배점 합계 100, n/a 가능 배점은 A3 3 + C1 5 + D2 10 = 18이다. 정상 입력에서 P는 최소 82이므로 P=0 방어는 도달 불가능하지만 모순은 아니다.

마지막 사례는 7점 항목 하나 fail, 다른 7점 항목 하나 partial이면 실제 배점으로도 성립한다. 반올림 뒤 등급이라는 명시된 선택을 따르므로 A는 오류가 아니다. coverage는 반올림 전 비율로 분기한다.

### 1.3 R2 잔여 조건의 구체 반례와 최소 종결안

**최신성(R2-4).** B6에 읽힌 날짜가 120일 전 하나뿐이고 더 최신 게시물이 있는 구간을 읽지 못했다면, 목록 최대값은 120일 전이어도 fail을 증명하지 못한다. 완전한 목록 또는 최신 작성일임을 보장한 정렬/필드를 확인하지 못하면 unknown으로 둔다. 읽은 날짜가 10일 전이라면 최신성이 일부 미확인이어도 적어도 30일 이내 소식 존재는 입증하므로 pass는 가능하다. 31~90일 partial·90일 초과 fail에는 놓친 더 최신 소식이 없다는 근거가 필요하다. 수집 범위를 늘리라는 요구가 아니다.

**정규화(R2-6·7·11).** 아래는 문서 규칙에 합성 문자열을 대입한 결과이며 실제 네이버 응답이라고 주장하지 않는다.

| 입력 | v0.6 규칙의 문제 | 최소 종결안 |
|---|---|---|
| `서울특별시 중구 세종대로 10 별관동` | 공백 fallback은 `별관동`을 선택할 수 있음. 숫자 건물동만 제외해선 부족 | 주소의 행정 부분에서 확인된 지역만 사용. 건물명인지 불명인 후보는 생략하고 확인된 구·군·시 사용 |
| `경기도 성남시 분당구 판교역로 10` | 동 후보가 없고 시·구 후보가 둘인데 선택 순서 없음 | 확인된 후보 중 더 작은 행정 단위 우선으로 고정 |

| `미용실 > 남성전문` | 명시적인 복합 category→select 매핑이 없어 기본 ‘추천’으로 빠짐 | 실제 지원 값만 작은 명시 매핑으로 확정; 확인하지 못한 값은 일반 추천 접미 사용 가능. 음식점 여부를 추정해 맛집으로 보내지 않음 |

별칭표 20쌍을 확대할 필요는 없다. 지원하는 값만 명시하고 나머지 ‘업종·메뉴 없음’ 검사를 보류하면 된다. 역 후보의 원래 순서를 사용하려면 그 순서가 무엇인지 §7에서 확인한다. 첫 연결 역이라는 사실만 확보했다면 Q&A에서 ‘가까운 역’이라는 거리 의미까지 보장한 것으로 취급하지 않는다.

**상태 전이(R2-8·9).** 다음은 빠진 경로를 메우는 최소 수정이며 새 서비스나 장기 재시도 기능은 필요 없다.

| 쿨다운 만료 후 시험 홈이 404·마커 없음·깨진 JSON·timeout | 성공/차단 이외의 시험 종료 전이가 없음. fetch 슬롯만 해제해도 시험 소유권이 남을 수 있음 | 해당 요청 폴백 후 시험 소유권을 반드시 해제. 비차단 실패는 정상으로 복귀하는 것으로 고정하면 가장 단순함 |

일반 timeout과 차단을 같게 보아 매번 30분을 연장할 필요는 없다. 비차단 종료와 명시 차단을 구별하고 모든 경로에서 대기 응답과 시험 소유권이 끝나게 하면 된다. 캐시 hit 우선과 부분 결과 캐시 허용은 v0.6이 명시한 선택이므로 자체 결함으로 보지 않는다.

처리량의 2,400 fetch/시, 4회 수집 기준 600매장/시는 이상적인 상한으로 맞다. 2,000매장×4회는 8,000 fetch이며 시작 간격만 약 3시간 20분이다. 따라서 §5의 ‘2,000매장 첫날 전부는 불가’는 이 산식에서 도출되지 않는다. ‘동시 유입 전부를 90초 안에 처리할 수 없음’으로 고치면 충분하다(성능 설명의 Minor이며 사업성 판정이 아님).

## 2 신규 이슈 R3-n | 심각도 | 대상 | 근거 | 문제 | 제안

R2에서 이미 지적한 같은 반례는 §1에만 남겼다. 아래는 이번에 처음 확인한 결함이다.

| R3-n | 심각도 | 대상 | 근거 | 문제 | 제안 |
|---|---|---|---|---|---|
| R3-1 | Major | 04번 §1.1 C3·§2 날짜/캐시 | C3는 유효기간 내 pass, 전부 empty fail, ‘만료분은 empty 취급’, 기간 missing unknown만 규정 | as_of=2026-09-14, 쿠폰 1개 시작=09-15·종료=09-20, 이벤트는 확인된 빈 목록. 기간은 모두 읽었지만 아직 시작 전이다. 진행 중이 아니므로 fail이어야 하나, 예정 쿠폰은 value이고 만료도 missing도 아니어서 어느 분기로도 확정되지 않는다 | 기간이 유효한 항목은 `시작≤as_of≤종료`일 때만 진행 중. 관련 목록·기간을 모두 확인했고 진행 중 항목이 0이면 예정/만료를 포함해 fail, 기간 미확인이 남으면 unknown. 캐시에는 시작·종료 절대 날짜를 보존하고 새 as_of로 이 파생 판정을 다시 수행. 수집 시점의 ‘비활성→empty’로 원래 기간을 지우지 않음 |
| R3-2 | Minor | 04번 §1·§2·§8 및 참조 항목표의 ‘19항목’ | 실제 ID는 A1~A4 4개, B1~B7 7개, C1~C4 4개, D1~D3 3개로 **18개**. 배점은 20+40+15+25=100으로 정상 | 고정 상수 길이·회귀 기대값을 19로 잡으면 문서의 실제 목록과 어긋남. 이번 검토 요청과 R2도 같은 수를 답습했음 | 문항을 추가하지 말고 실제 열거한 **18개·100점**을 구현 기준으로 확정. ‘19’라는 개수 표기와 테스트 기대값만 정정 |

R3-1은 날짜 입력 규칙 자체나 산식 오류가 아니다. C3에서 유효하지만 아직 진행하지 않은 값의 분기가 누락된 문제다. 24시간 facts 캐시와 새 as_of 정책을 유지하려면 원래 기간을 남겨야 한다. 09-14 23:50 수집 후 09-15 00:10 캐시 hit에서는 같은 예정 쿠폰이 진행 중으로 바뀌어야 한다.

## 3 잔여 Minor(구현 중 처리 가능)

- **문항 개수:** R3-2대로 18개·100점 고정. 누락된 19번째 문항을 만들지 않는다.
- **보충 수정·취소:** 최초 전부 unknown이면 `[D1,D2,B2,B5,B6]` 선택. D1=리뷰 없음이면 D2만 숨기고 4개가 남으며 대체하지 않는다. D1을 날짜/미응답으로 바꾸면 최초 후보에 있던 D2만 다시 표시한다. 수동 원답은 보존하고 n/a는 파생 상태로 계산하면 된다. 처음 후보가 아니었던 D2를 추가하지 않는다.
- **기준일 및 정규화:** 날짜는 Asia/Seoul 달력 날짜를 기준으로 정수 일수 차를 계산한다. B1은 NFC→trim→코드포인트 길이, B2의 5 초과·잘못된 원소 타입은 unknown으로 고정한다. D3의 확인된 빈 원문과 미제출 입력은 구별한다.
- **URL 최소 경계:** `new URL` 등으로 호스트와 pathname을 분리한 뒤 경로 세그먼트를 일치시킨다. m.place/pcmap의 고정 ID 위치, map의 `entry/place`와 `search/{q}/place`는 서로 겹치지 않는다. type 생략 기본값은 type을 주지 않는 지도 패턴에 적용하면 된다. 모바일 쿼리형·scheme 없는 입력·place 없는 검색 URL은 ‘그 외 미지원’에 포함되어 기능 누락으로 보지 않는다.
- **URL 테스트 고정:** 탭 없음/`home?entry=pll#x`, hospital 경로, `/p/search/안국/place/123`, `/v5/entry/place/123`, 숫자가 검색어에만 있는 URL, 문장 안 URL, 단축→지원/미지원/해석 실패를 합성 입력으로 확인한다. ID 전체가 십진 숫자 세그먼트인지 검사하고 `123abc`의 일부 숫자를 채택하지 않는다. 인코딩된 검색어 안 `/place/숫자`를 경로로 오인하지 않도록 pathname을 통째로 디코딩한 뒤 검색하지 않는다. 공유 문장의 URL 종료 문자도 파서 테스트에서 한 가지로 고정한다.
- **표현과 참조의 기계적 정정:** A4의 ‘스파이크 §7-1’은 찾아오는 길인 §7-5. ‘2,000매장 첫날 전부 불가’는 위 산식으로 입증되지 않으므로 ‘동시 유입을 90초 안에 전부 처리 불가’로 정정한다. 반환하는 접수 시 순번을 실시간 순번으로 표시하지 않는다.
- **한도 경계:** 큐 200개를 상한으로 삼는다면 새 작업을 더했을 때 200을 넘는 요청부터 거절한다. 같은 작업 합류는 새 작업 추가가 아니다. 예상 대기는 고정 계산식을 사용하되 실제 90초 종료를 대체하지 못한다.

## 4 구현 착수 체크리스트 최종본

완료 표시는 **명세상 확정된 것**이다. 실제 구현/테스트 완료 표시는 아니다. 미완료 중 첫 항목은 남은 Blocker, 다음 항목들은 기존 기능을 구현할 때 함께 닫을 조건이다.

- [ ] **R2-1 Blocker 해소:** 공통 관측 해석과 행 판정을 분리. A2 숨김, A3/C4 empty→unknown, D3 검사 완료 빈 원문→pass, D1 총수 0 및 D2 n/a 우선, B3 empty+missing→unknown, 수치/날짜 value→fail을 한 가지 결과로 고정.
- [x] **산식:** P·K·E·coverage·반올림 후 등급, 0 known, 0.50/0.70 경계, D1 보충 후 P=90·K=90·E=82·91점 확정.
- [x] **보충 범위:** 고정 순서의 최초 최대 5개, D2 숨김 후 대체 없음, raw 병합 후 전체 재판정, 공유 캐시에 수동 답을 쓰지 않음, 폴백은 기존 3탭.
- [ ] **최신성:** B6 partial/fail에 필요한 최신성 근거를 확인하지 못하면 unknown. D2의 최신 답글 증명과 D3의 정한 검사 범위 완료 여부를 보존.
- [ ] **정규화:** 확인된 주소 토큰과 명시 순서 사용, 노선 괄호 역명 처리, 메뉴 의미 보존, 지원 category 매핑만 적용. 역 순서·category 매핑 확인을 기존 스파이크 목록에 포함.
- [ ] **C3 기간:** R3-1의 예정/진행/만료 분기 및 기간 미확인 처리 고정. 원래 날짜를 facts에 보존하고 캐시 hit의 새 as_of로 재평가.
- [ ] **요청 종료:** 추가 탭/단축 해석을 포함한 차단 처리, 시험의 비차단 실패 복귀와 시험 중 유입, 실제 90초 마감 시 응답·대기 제거·슬롯/시험 소유권 해제를 확정.
- [ ] **요청 예산:** 단축 해석 포함 총 4회. 남은 예산에서 탭 고정 우선순위 적용, 읽지 못한 탭은 missing. 모든 외부 요청에 동시 1·시작 간격 1.5초·8초 timeout 적용.
- [x] **URL 범위:** 지원/미지원 목록과 단축 1회 후 재판정 확정. 미지원 URL 확대 지원은 요구하지 않음.
- [x] **날짜·캐시:** 절대 날짜·수집시각 보존, 새 진단은 새 as_of, 보충은 최초 as_of 고정. 부분 캐시는 부분 표시를 유지하고 실패/폴백은 저장하지 않음.
- [ ] **Minor 반영:** 실제 18개·100점, 최초 보충 후보의 수정/취소 복원, URL 세그먼트 경계, 큐 한도와 참조 번호 정정.
- [x] **검증 방식:** 실제 픽스처와 합성 HTML·fake fetch·주입 시계의 회귀 매트릭스 채택.
- [ ] **구현 후 검증:** 위 행별 반례·산식 표·전이 누락 경로·R3-1 자정 전후 캐시 사례를 네트워크 없이 재현하고 통과 확인. 이 검토에서 수행하지 않은 실측은 별도 사실로 기록하며, 확인 불가능한 원천은 unknown/기존 보충으로 종료.

이 조건을 반영하면 **구현 착수 가능**으로 전환할 수 있다. 추가 문항·추가 수집·외부 서비스 도입은 수용 조건이 아니다.
