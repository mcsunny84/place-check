## 0. 검토 범위 변경 고지 (태양 결정, 55번 §9)

56번 작성 중에 태양이 결정을 추가했다: **무료 배포(오픈채팅 약 2,000명)이므로 보안·약관 등 비기능 항목은 타이트하게 보지 말 것. 적대 검증은 동작 정확성(채점 결정론·처방 매핑·계산 오류·구현 계약)에 집중.** 약관 보수 해석을 이유로 한 Blocker는 두지 않는다. 53번과 같은 사업 판단이며 소유자는 태양이다.

# 네이버 플레이스 진단기 기획 v0.2

## 3. 제품 정의 (변경 없음)

"내 네이버 플레이스가 얼마나 채워져 있고 무엇부터 채워야 하는지"를 보여주고, 채울 초안까지 만들어 주는 도구. 순위 예측·보장 없음. 우열 비교 없음. 사장님이 스마트플레이스에서 직접 통제 가능한 항목만.

## 4. 항목표 v2 — 23항목, 4그룹, 합 100

### 4.0 공통 규칙 (전 항목)

- state 어휘: `pass / partial / fail / unknown / not_applicable` (geo-scoring VALID_STATES).
- **미응답·형식 오류·판독 불가 = `unknown`** (부재 아님, 06번 P-6). `fail`은 사장님이 "없음/0/아니오"라고 명시 응답한 경우에만.
- 수치 입력: 정수만 허용(문자열 숫자는 trim 후 `/^\d+$/` 통과 시 정수 변환). 음수·소수·그 외 = unknown. 상한 9,999.
- 날짜 입력: `YYYY-MM-DD` 문자열만. 기준 시각 `asOf`(ISO, 호출자 주입 — Tier 0은 브라우저 `new Date()`, 테스트는 고정값). 일수 계산 = KST 자정 기준 정수 일 차이. 경계 **포함**(30일 규칙: 0≤diff≤30 pass). 미래 날짜(diff<0) = unknown. 파싱 실패 = unknown.
- 텍스트 길이: NFC 정규화 → trim → `Array.from(str).length`(코드포인트 수). 공백·줄바꿈만이면 길이 0.
- n/a는 사장님이 해당 항목의 "해당 없음" 옵션을 명시 선택한 경우만. 기본값 아님.
- 각 항목 레코드: `{ id, state, input, observed_at: asOf, source: 'self_reported' | 'naver_local_api' }`.

### 4.3 채점 함수 계약 `computePlaceScore(items, { asOf })` — lib/place-scoring.js

- `PLACE_ITEMS` = 위 23개 `{id, weight, group}` 고정 상수(순서 = 표 순서). `SCORE_VERSION = 'place-1.0.0'`.
- 입력 검증: id는 PLACE_ITEMS 집합과 **정확히 일치**해야 함(누락·중복·미지 키 → throw). 호출자는 미수집 항목을 `unknown`으로 채워 넘긴다(채우는 helper `fillUnknown(partialItems)` 제공).
- 계산: geo-scoring `computeScore`의 산식 복제(known 배점 합 / 적용 배점 합, unknown 미감점, n/a 분모 제외, coverage 경계 0.70 점수 / 0.50 등급 / 미만 "평가 불충분"). geo 함수를 직접 호출하지 않는다(6개 고정 키 제약).
- 반환: `{ score_version, score|null, grade|null, display_state, data_coverage, groups: {A,B,C,D: {earned, applicable, known}}, items }`.
- 필수 테스트(표 기반): 0 known / 전체 n/a / coverage 0.50·0.70 경계 / Tier 0 최대 0.88 / 누락 키 throw / 각 항목 pass·partial·fail·unknown·n/a 전이 / 날짜 경계(diff 30·31, 미래, 파싱 실패) / 정수 검증(음수·소수·문자열).

### 4.4 A1~A3 귀속 판정 (R1-4)

- `resolveBranchAttribution({ candidates, name, branch })` → `{ verdict: 'branch_match' | 'brand_only' | 'none' | 'ambiguous', candidate }`.
- 규칙: `judgeMention`이 `branch_mentioned=true`인 후보 1개 → branch_match. 2개 이상 → ambiguous. 0개인데 brand_mentioned 후보 있음 → brand_only. 없음 → none.
- 채점 매핑: branch_match만 A1 pass·A2/A3 평가. brand_only·ambiguous·none·호출 실패 전부 **A1~A3 unknown**. 지점 미입력 시(단일 매장) branch 조건을 address_district == 소유자 입력 시·구로 대체, 불일치면 unknown.
- 테스트: 56번 합성 입력(키세카츠 강남점 후보 + 안국역점 요청)이 A1 unknown이 되는지 고정.

## 6. 처방·우선순위 (R1-8·R1-10)

- 처방 매핑표는 55번 §5 유지. 단 Tier 0에서는 **로컬 고정 문안만** 렌더(카피 엔진·마케팅 글 작성기 호출 없음). "초안 만들기" 버튼 = marketing-lab 별도 페이지로 **이동만**(URL 파라미터·답변·상태 전송 0). 그 페이지가 자기 원천 사실을 새로 받는다.
- 우선순위 함수 `pickWeeklyTodos(items)`:
  1. D4가 fail이면 **슬롯 1 고정**.
  2. 나머지 슬롯: `weight × (fail=1, partial=0.5)` 내림차순, 동률은 **항목 ID 문자열 오름차순**(A1<A2<…<D4).
  3. 처방 매핑이 없는 ID는 후보에서 제외(빈 카드 방지). 같은 ID는 1슬롯.
  4. 반환 정확히 3개 이하.
- Tier 1 안내 분리: 채점 state와 별개로 `todosFromAnswers(answers)`(pre-git seo-checklist 패턴)가 self_reported 답에서 고정 문안 할 일을 생성. 점수 state에 편입하지 않는다.
- 테스트: 56번 반례(D2=B2=B3=D4=fail → D4 포함), B2·B3 동률 순서, 매핑 없는 항목 제외.

## 7. 저장·게이트 (R1-9)

- Tier 0: 저장 없음 → 게이트·원장 대상 아님. 계약 준수는 **정적 파일에 fetch/XMLHttpRequest/localStorage/sessionStorage/IndexedDB 문자열이 없음을 검사하는 테스트**로 고정(check:leaks 유형).
- Tier 1: 결과 객체 `result.place = { score_version, items, groups, score, grade, display_state, attribution, naver_scale }`. 
  - `validatePlaceResult` strict(정확한 키 집합, self_reported 원문 값은 **저장 금지** — items에는 state와 source만, input은 세션 응답에서만).
  - publish-gate `collectProseFields`에 `place.todos[].text`·`place.items[].note` 경로 등록. `checkPublishable(result, { tool: 'geo' })` 그대로(별도 tool 스코프 신설 안 함 — geo 결과의 하위 필드로 편입).
  - job-commit optional 검증 블록에 `validatePlaceResult` 추가.
  - sentinel 테스트: 56번 우회 입력(`place.todos[].text = '리뷰 작성 시 쿠폰 증정'`)이 `review_incentive`로 차단되는지, self_reported input 값이 캐시 직렬화에 없는지.

## 8. 배포·재측정 (R1-10·R1-11)

- Tier 0 정적 파일 **2개**: `public/place-self-check.html` + `public/place-scoring.js`(lib/place-scoring.js와 동일 소스 — UMD, 테스트가 두 파일 동일성 단언). 외부 의존성 0. 배포는 githack 또는 marketing-lab 공개 경로.
- Tier 0 재측정: 없음. 사장님이 다시 하면 새 결과. "결과 저장" 기능 없음(무저장 원칙).
- Tier 1 재측정: `baseline.place` discriminant 신설 — `{ score_version, item_ids(23 고정), attribution.verdict, observed_at }`. 비교는 동일 score_version·동일 attribution candidate에서만. measurement.js의 tech_audit 경로와 독립(구 캐시 무영향 테스트). 상세는 구현 문서.
