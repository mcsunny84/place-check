## 1. 관측 3상태와 19행 판정 (R2-1·3·4)

### 1.0 파서 출력 규약

facts의 모든 원천 필드는 `{ status: 'missing' | 'empty' | 'value', value?, read_at }` 이다.
- `missing`: 키 없음·타입 불일치·참조 미해결·해당 탭 fetch 실패·JSON 파싱 실패.
- `empty`: 키가 있고 값이 null·''·[]·false 등 **확인된 빈 값**.
- `value`: 유효 값.

판정 공통 규칙(행 규칙보다 우선):
- 긍정 증거(value, 조건 충족) 1개 → `pass`(또는 행 규칙의 partial).
- 관련 원천 **전부 empty** → `fail`.
- 그 외(하나라도 missing) → `unknown`.
- 스파이크에서 "empty가 미등록을 뜻하지 않는다"고 확인된 필드는 empty도 unknown으로 취급(필드별 플래그 `empty_means_absent: false`).

## 2. 산식·날짜 (R2-2·12)

```
n/a 제외 후: P = Σw(pass,partial,fail,unknown)   K = Σw(pass,partial,fail)   E = Σw(pass) + 0.5·Σw(partial)
coverage = K / P            (P=0 이면 insufficient)
score    = K>0 ? round(100·E/K) : null      (round = 사사오입 정수, 등급은 반올림 후 점수로)
display  = coverage ≥ 0.70 → 'score' / ≥ 0.50 → 'grade' / 그 외 'insufficient'
grade    = 90+ A / 75~89 B / 60~74 C / <60 D   (display가 score·grade일 때만)
```
- 검산(03번 사례): 82점 pass, D1·D2 unknown → P=100, K=82, E=82, coverage 0.82, score 100. 보충 D1="리뷰 없음" → D1 fail(8), D2 n/a(10) → P=90, K=90, E=82, coverage 1.00, score 91. D2가 unknown 유지 시 P=100, K=90, coverage 0.90.
- 보충 재계산은 **raw answers 병합(자동 raw + 수동 raw) → 19항목 전체 재판정 → 재집계**. state 문자열 전달 금지.
- 날짜: facts에는 `YYYY-MM-DD` 절대 날짜(Asia/Seoul로 정규화)와 `fetched_at`(ISO)만. 서버 응답에 `as_of: 'YYYY-MM-DD'`(Asia/Seoul 오늘)를 포함하고 브라우저 재계산은 이 값을 그대로 주입한다. 캐시 hit로 새 진단을 만들 때도 as_of는 새로 찍는다. 연도 없는 날짜·상대 표현·미래·파싱 실패 = missing.

## 3. 보충 질문·폴백 (R2-5)

- 후보 = unknown 항목 중 아래 고정 순서로 최대 5개, **진단 1회당 1회만 표시**: `D1, D2, B2, B5, B6, C1, A3, A4, C3, C4, B4`.
- D1 답이 "리뷰 없음"이면 D2는 즉시 n/a로 숨김(대체 질문 안 넣음 — 총한도 5 유지).
- 보충 답은 세션 answers에만 병합, facts 캐시에 쓰지 않음.
- 자동 화면의 키워드·초안: 확보된 문자열만 사용. 동네·역·메뉴 중 빠진 것은 그 섹션 안에 소형 입력칸으로 보충(점수 문항과 무관, 브라우저 내 계산).
- 폴백(홈 판독 불가·큐 초과·쿨다운)은 **v0.4 3탭 전체**(19문항 + 키워드 입력 + 초안 입력). 자동 화면에 이 폼을 섞지 않는다.

## 5. 큐·캐시·쿨다운 전이표 (R2-8·9) — 03번 제안 채택

| 조건/사건 | 처리 |
|---|---|
| 유효 facts 캐시(24h) 있음 | 쿨다운 무관 즉시 반환 |
| 캐시 miss + 쿨다운 중 | 큐에 넣지 않고 즉시 폴백(reason: cooldown) |
| 정상 + miss | 같은 placeId 진행 작업 있으면 합류, 없으면 작업 1개 추가. **실행 직전 캐시 재확인** |
| 큐 길이 > 200 또는 예상 대기 > 90초 | 즉시 폴백(reason: busy) |
| fetch 1회 타임아웃 8초, 매장당 외부 요청 ≤4(단축 URL 해석 1회 포함), 요청 **시작 간격** 1.5초(모든 외부 요청 공통) | 타임아웃·예외·정상 종료 모두 슬롯 해제 |
| 홈 성공, 추가 탭 실패 | 부분 결과(해당 필드 missing) — 캐시 저장함(부분 표시 플래그) |
| 홈 판독 실패(비차단: 404·마커 없음·JSON 깨짐) | 그 요청만 폴백(reason: unreadable). 쿨다운 **아님** |
| 429 또는 캡차 문구(홈 응답) | 서버 공통 쿨다운 30분 시작(종료시각 기록), 진행·대기 작업 전부 폴백 종료, 새 외부 요청 중지 |
| 쿨다운 만료 | 다음 miss 작업 **1개만** 시험. 성공→정상, 차단→30분 재설정. 쿨다운 중 유입은 종료시각 연장 안 함 |
| 실패·폴백 결과 | 캐시 안 함 |
| IP 한도 | **새 수집 작업 생성** 기준 분당 3회(슬라이딩 60초). 캐시 hit·보충 재계산·폴백은 미포함. 초과 → 429 JSON + "잠시 후 다시" |
| 응답 방식 | POST 1회가 최대 90초 대기(long-poll). 접수 시 순번을 즉시 헤더로 알리지 않고 응답 본문에 `queued_position`(접수 시점)만 포함 |

처리량 정정: 시작 간격 1.5초 → 시간당 외부 요청 ≤2,400 → **4회/매장이면 ≤600매장/시**. 2,000매장 첫날 전부는 불가 — 대기 초과분은 폴백(셀프 체크)으로 흡수. 이게 무료 도구의 한계이며 태양에게 고지(E7 확정 근거).

## 6. URL 파서 (R2-10)

지원(placeId 추출 위치 고정):
- `m.place.naver.com/{type}/{id}` `(/{tab})?` `?…` `#…` — type ∈ restaurant|cafe|place|hospital|hairshop|accommodation|기타 영문. type은 pcmap 요청 경로에 그대로 사용, 없으면 `place`.
- `pcmap.place.naver.com/{type}/{id}…`
- `map.naver.com/p/entry/place/{id}`, `map.naver.com/p/search/{q}/place/{id}`, `map.naver.com/v5/entry/place/{id}`
- `naver.me/{token}` → 리다이렉트 1회(외부 요청 예산 포함) → 위 규칙 재적용. 도착지가 위 패턴 아니면 미지원.
- 붙여넣은 문장 안의 첫 `https?://` URL 추출.
미지원(안내 문구 + 셀프 폼 진입): `m.map.naver.com/search2/site.naver?code=`, 검색 결과 URL(place 없음), 그 외. 임의 숫자 검색 금지.
스파이크: `pcmap …/place/{id}/home`이 type 불일치에도 200인지 확인.
