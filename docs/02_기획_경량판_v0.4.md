## 2. 항목표 v3 — 19문항, 4그룹, 합 100

공식 표기(55-B 실사 반영): 상호→**업체명**, 소개문→**상세설명**, 브레이크타임→**휴게 시간**, 대표키워드 **최대 5개**. 인테리어·외관 사진 구분은 사장님 입력 항목이 아니라 **삭제**. 메뉴 사진은 개별 필드 불명이라 **예/아니오**로 단순화.

### 2.0 공통 규칙

- 미응답·형식 오류 = `unknown` (감점 없음, 분모에는 남음). `fail`은 "없음/0/아니오" 명시 응답만.
- 정수 입력: trim 후 `/^\d+$/` 통과 시만 정수. 그 외 unknown. 상한 9,999.
- 날짜 입력: `<input type="date">` 값(`YYYY-MM-DD`). 기준일 `asOf`(호출자 주입, 화면은 오늘). 일수 = 두 날짜의 자정 기준 정수 차(로컬 시간대). 경계 포함. 미래 날짜·파싱 실패 = unknown.
- 글자 수: NFC 정규화 → trim → `Array.from(s).length`.
- n/a는 "해당 없음" 옵션을 명시 선택한 경우만.

### 2.2 채점 함수 `computeScore(answers, { asOf })` — place-scoring.js

- `ITEMS` 19개 `{id, group, weight}` 고정 상수, `SCORE_VERSION='place-check-1.0'`.
- 입력 `answers`: `{ [id]: rawValue }`. 없는 id는 unknown으로 채움. 미지 id는 무시(throw 아님 — 정적 페이지는 관대하게).
- 각 항목 `judge_<id>(raw, ctx)` 순수 함수 → state. D2는 ctx에 D1 상태 필요(D1 raw="none"이면 n/a).
- 반환 `{ version, score, grade, coverage, display: 'score'|'grade'|'insufficient', groups: {A,B,C,D:{earned,applicable,known}}, items:[{id,state,weight}] }`.
- 테스트(node --test, 의존성 0): 각 항목 5-state 전이, 정수/날짜 경계(30·31·90·91·180·181, 미래, 빈 값), D2 n/a 연동, 전부 unknown → insufficient, 전부 n/a 가능 항목만 n/a일 때 분모, 합계 100, coverage 0.50/0.70 경계.

### 2.4 항목별 고정 문안 (copy.js)

각 ID에 `{ why: 1문장, how: 스마트플레이스 메뉴 경로 + 2~3문장, tip: 선택 }`. 예: B2 → "스마트플레이스 > 업체정보 > 상세정보 > 대표키워드. '동네+메뉴', '역이름+업종' 조합으로 5개 채우기. 예: 안국역 돈카츠, 안국 맛집…". 순위·매출 약속 문구 금지(자체 원칙, 계약 아님).


### 2.5 대표키워드 진단·추천·노출 셀프체크 (점수 밖 별도 섹션, keyword.js)

플레이스에서 가장 중요한 입력이 대표키워드라 별도 섹션으로 둔다. 점수(§2.1 B2 개수)와 분리 — 여기서는 **내용**을 본다.

입력: ① 현재 등록한 대표키워드 최대 5개(텍스트) ② 동네/상권(예: 안국동) ③ 가까운 역(예: 안국역, 선택) ④ 업종 1개(예: 돈카츠) ⑤ 대표메뉴 1~2개(예: 로스카츠) ⑥ 상황 태그 select 다중(회식·혼밥·데이트·아이동반·포장·배달·주차 중 선택).

**(1) 현재 키워드 진단 — 키워드별 결정론 판정, 라벨 1개 이상**

| 검사 | 규칙 | 라벨·문안 |
|---|---|---|
| 브랜드명 단독 | 키워드가 업체명(입력값)과 NFC·공백 제거 동등 | "업체명은 검색하면 어차피 나와요 — 자리 낭비" |
| 지역 없음 | 동네·역·행정구(시·구·동 접미) 토큰이 하나도 없음 | "지역이 없어요 — 동네나 역을 붙이세요" |
| 업종·메뉴 없음 | 업종·대표메뉴 토큰이 없음 | "뭘 파는지 없어요" |
| 너무 넓음 | 토큰 1개(예: "맛집", "돈카츠") | "혼자서는 못 이겨요 — 지역+업종으로" |
| 중복 | 다른 키워드와 공백 제거 후 동등 | "중복" |
| 길이 | 코드포인트 2 미만 또는 20 초과 | "길이 이상" |
| 좋음 | 위 해당 없음 + 지역 토큰 + 업종/메뉴 토큰 둘 다 있음 | "좋아요" |

토큰화: 공백 분리 + 입력받은 동네·역·업종·메뉴 문자열의 부분 문자열 포함 검사(한국어 띄어쓰기 변형 대응 — "안국역돈카츠"도 지역·업종 검출). 접미 사전: 역·동·구·시·읍·면·리·사거리·거리·시장·단지.

**(2) 추천 키워드 10개 — 고정 템플릿 조합 (순서 고정 = 우선순위)**

| # | 템플릿 | 예 |
|---|---|---|
| 1 | `{동네} {업종}` | 안국 돈카츠 |
| 2 | `{역} {업종}` | 안국역 돈카츠 |
| 3 | `{동네} 맛집` | 안국 맛집 |
| 4 | `{역} 맛집` | 안국역 맛집 |
| 5 | `{동네} {대표메뉴1}` | 안국 로스카츠 |
| 6 | `{역} {대표메뉴1}` | 안국역 로스카츠 |
| 7 | `{동네} {상황1} {업종}` | 안국 혼밥 돈카츠 |
| 8 | `{역} {상황1}` | 안국역 혼밥 |
| 9 | `{동네} {업종} 추천` | 안국 돈카츠 추천 |
| 10 | `{동네} {대표메뉴2}` (없으면 `{역} {상황2}`) | — |

- 빈 변수(역·메뉴2·상황)가 들어가는 템플릿은 건너뛴다. 현재 등록 키워드와 동등한 것은 "이미 등록" 표시. 음식점 외 업종은 "맛집" 대신 업종별 접미 표(미용실→"잘하는 곳", 병원·의원→"추천", 학원→"추천", 기본→"추천") 사용 — 업종 select 값으로 결정.
- 화면: "현재 5개 중 바꿀 만한 것" = (1)에서 "좋아요" 아닌 키워드, 그 자리에 (2) 상위 후보를 넣는 제안 표. 순위·검색량 예측은 하지 않는다.

**(3) 노출 셀프체크 (사장님이 직접 검색해 표시)**

- 안내: "네이버 지도 앱에서 아래 키워드를 검색하고, 우리 가게가 어디 나오는지 골라주세요" — 현재 키워드 5개 + 추천 상위 3개.
- 선택지: 1페이지(상위 10) / 2~3페이지 / 안 보임 / 안 해봄. 결정론 문안: 1페이지 → "지키세요", 2~3페이지 → "소식·사진·리뷰 답글로 밀어올릴 여지", 안 보임 → "이 키워드는 경쟁이 세거나 정보가 안 맞아요 — 대체 후보 검토", 안 해봄 → 표시 안 함.
- **검색량 조회는 링크 아웃**: 네이버 검색광고 키워드도구(https://searchad.naver.com) 안내 문구 + "월간 검색수 100 미만이면 후순위" 같은 판단 기준만 제공. 정적 페이지에서 조회는 하지 않는다(서버·API 없음).

### 2.6 GEO용 Q&A식 상세설명 초안 (점수 밖, draft.js)

AI 검색(구글 AI 개요·챗GPT·네이버 AI 브리핑)이 답변에 끌어다 쓰기 좋은 형태 = **질문-답 쌍 + 구체 사실**. 이를 결정론 템플릿으로 생성해 사장님이 복사해 스마트플레이스 상세설명(글자 한도 확인 필요 — 55-B 미확인, 화면에 "한도 초과 시 앞부분부터 잘라 쓰세요" 고지)에 붙여넣게 한다.

입력(§2.5와 공유 + 추가): 업체명, 동네, 역, 업종, 대표메뉴 1~2 + 가격(선택), 영업시간 요약 1줄, 휴무, 주차(가능/불가/근처 유료), 예약(네이버예약/전화/불가), 포장·배달(예/아니오), 좌석·단체(선택), 한 줄 자랑(선택 — 유일한 자유 텍스트).

출력 구조(고정 순서, 빈 입력 문단은 생략):

```
[업체명]은 [역] 근처 [동네]에 있는 [업종] 전문점입니다. 대표 메뉴는 [메뉴1]([가격])과 [메뉴2]입니다. [한 줄 자랑]

Q. [동네]에서 [업종] 어디가 좋아요?
```

- 조사(은/는, 을/를) 처리: 마지막 글자 받침 유무로 결정론 선택(유니코드 한글 범위 계산). 영문·숫자로 끝나면 "은/는" 기본.
